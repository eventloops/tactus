### M4, the one survivor, is a redundancy and not a hole

The check M4 removes is **logically implied by two checks that both run before it** in the same
function, so no test can kill it:

1. `check_merge_prepared` opens by calling `MergePrepared::self_consistency()`, whose `Fast` arm
   refuses `FastProposesAnotherCommit` unless `proposed_sha == candidate_sha`.
2. It then calls `prepared_candidate(…, &prepared.candidate())`, which selects the recorded
   `PreparedCandidate` by `.filter(|prepared| prepared.candidate == *candidate)` — **full**
   `CandidateRef` equality, `commit_sha` included — and `MergePrepared::candidate()` builds that
   `CandidateRef` from `self.candidate_sha`. So reaching the third check at all requires
   `candidate_sha == candidate_record.candidate.commit_sha`.

(1) and (2) give `proposed_sha == candidate_record.candidate.commit_sha`, which is exactly what M4
deletes. The pair is *jointly* guarded — M6 shows that removing (1) alone is caught in 2 tests — so
the guarantee has a live witness; the third statement of it does not, and cannot. This is the
"redundant assertion defeats its own mutation" shape, not a coverage gap. **Not a finding.** It is
worth a one-line note in the source for the next reviewer, who will run the same mutation and reach
the same dead end.

Two of the kills deserve to be named for what they are, because they are the pass rule's own clauses:

- `every_guarded_event_is_refused_the_same_way_live_and_on_a_hostile_replay` (`topology/fold/tests.rs`)
  is the mechanical proof that a refusal is *the same* live and on replay. Over three traces, at every
  position, it builds one-field-invalid variants, asserts `plan_transition` refuses **live**, then
  builds a hostile log that is the trace **with exactly one line replaced** (asserted, so the
  perturbation cannot degenerate), serialises it to the wire, parses it, replays it, and asserts the
  replay's error is **equal** to the live error. Four event kinds are declared deliberately unguarded
  and named. Killed by M14 and M18.

  **Its breadth, stated precisely rather than generously:** `one_field_invalid` perturbs a fixed pair
  of fields per event kind — for `merge_prepared` those are `expected_head` and `candidate_ref`, not
  `proposed_sha`, `prepared_ref` or `disposition`. So this census proves *refusal equality across live
  and replay* for the fields it moves; it does **not** by itself cover the whole T-FAST relation set.
  That set is covered by the dedicated test, next.
- `merge_prepared_fast_with_moved_head_or_wrong_proposed_or_pin_refused_live_and_on_replay`
  (`integrate/tests.rs:257`) is the complete T-FAST relation proof, and it is built the right way
  round. It first asserts the **honest** `merge_prepared(fast)` *is accepted* — a positive control, so a

## 5. Required artifacts #4 and #5 — replay-twice equality, and one linear commit per task

### #4 replay-twice equality

`Run::replay_twice_equal()` (`src/engine/topology/scaffold.rs:1287`) is not a self-oracle. It reads
the **on-disk** log (`durable_events()` = `std::fs::read(log.path())` then `TopologyFold::parse_log`),
replays it twice from `FrozenInputs`, asserts the two folds' `state()` equal, and then asserts the
**live incrementally-folded state equals the replay** — which is the load-bearing third assertion:
the live fold is built by `apply_delta` as events are appended, the replay by `TopologyFold::replay`,
and only agreement between two different code paths over the same bytes is evidence.

It is called at the end of every terminal shape in
`terminal_shape_coverage_table_drives_every_shape_and_each_converges_on_replay` (all 7 shapes),
at the end of the fast-path proof, and in the two-crash proof — where the replay-twice is over the
log that survived a **real** simulated power loss.

### Q3 — stale, duplicate and out-of-order completions

**G3's portion.** A verification completion arriving for a sequence that is no longer open; a second
terminal for one transaction; a `task_merged` naming a SHA the authorization did not propose; and the
append-error protocol as it applies to an integration append.

- **Every event of an open transaction is keyed to the sequence.** `open_transaction(kind, sequence)`
  refuses with `WrongSequence` if no transaction is open, or if the open one's sequence differs.
  `check_merge_prepared` (stale/already_present), `check_verification_unavailable`,
  `check_verification_interrupted`, `check_merge_rejected` and `check_task_merged` all go through it.
  A completion for an interrupted sequence therefore cannot mutate the newer one: after
  `merge_verification_interrupted`, `release_transaction()` clears `self.transaction`, so the stale
  completion meets "none" and is refused.
- **A closed transaction cannot be reopened.** `check_transaction_start` refuses while one is open
  (M12) and requires the dense next sequence (M14), so a duplicate `merge_verification_started` for a
  resolved sequence is refused on both counts.
- **A `task_merged` cannot name a different object.** `check_task_merged` refuses
  `merged_sha != proposed_sha` of the open `Prepared` transaction (M18).
- **A returned append error cannot let a stale in-memory fold drive anything.** `emit()`
  (`src/engine/topology/emit.rs`) does, on an entered-and-failed append and in this order:
  `state.fold.poison()`, `state.reservations.cancel_any()`, then `establish_stable_prefix` to decide
  `Present` / `Absent` / `Undetermined{step, detail}` **by rereading the file**, never from memory.
  After poisoning, `TopologyFold::plan_transition` returns `FoldError::Poisoned` for **every** event,
  and `ready`, `ready_retry`, `pipeline_reservable` and the other predicates all return `false`. The
  error type is `#[must_use]` and its `Display` states the protocol it followed. There is no retry
  path: `T-RUNSTART`'s refusal list names "a retry of the first append after a returned error" and the
  same rule holds here by the poison.
- Witnessed end-to-end for the CAS specifically by
  `an_append_failure_at_merge_prepared_issues_no_cas_and_leaves_the_integration_ref`
  (`integrate/tests.rs:187`) and
  `an_append_error_during_recovery_cancels_the_reservation_and_every_running_invocation`.

**Q3 verdict: answered with evidence for the G3 portion.** Slot release, cancel and provisional
conversion under *concurrency* belong to PR11's broker and are out of range; what is in range — the
single-process provisional reservation — is covered by the reservation tests and M11/M12.

staging slot (`Some` iff `disposition != Fast`) from the recorded event; `lease_release` is re-derived

reconstructed from the log — it is observed from the ref inside `publish()`, which is the only correct
source. Witnesses: `a_resume_completes_a_prepared_fast_transaction_through_the_barrier_and_cas`
(ref at expected → CAS then `task_merged`), `a_resume_completes_a_prepared_transaction_whose_cas_already_ran_by_recording_the_merge`
(ref at proposed → `task_merged` only, `cas_integration_entries == 0`),
`a_resume_of_a_prepared_transaction_whose_ref_moved_elsewhere_refuses_a_third_sha` (M7), and
`a_recovered_authorization_is_the_live_one_and_completes_through_the_same_publish` — which is the
strongest of the four, because it asserts the recovered authorization is **the same value** the live
path built and that both complete through the same `publish`.

**(b) Do entitlements derive from recorded active generations and unresolved transactions?** Yes:
`pipeline_held()` and the merge entitlement are pure functions of `tasks[].open()` and
`transaction.is_some()`, both of which are fold state. Nothing about an entitlement is stored
separately, so there is nothing to disagree. `an_unresolved_verification_leaves_its_entitlements_with_the_open_transaction`.

**(c) Does every fresh process establish the stable-prefix barrier before any CAS?** Yes, and it is a
**typestate**, not a discipline. To reach `finish_integration` — the only recovery path to `publish` —
a caller must hold a `PreflightCertified`, which is constructible only from a `RunnerRebuilt`, which is
constructible only from a `ResumeCensused`, which holds a `BarrierHeld`, which is constructible only
from a `StablePrefix`. And `StablePrefix` has exactly one constructor in the crate:
`establish_stable_prefix` (`src/events/log.rs:878`), which
(i) opens through `EventLog::open_funnel`, truncating a torn tail and **fsyncing** the surviving
prefix (`sync_log_file`, failures mapped to `BarrierStep::SyncPrefix`);
(ii) rereads the file and refuses unless it ends at a commit marker, is the same **length** as the
prefix synced at open, and is **byte-equal** to it, naming the first differing byte if not;
(iii) refuses unless the first line's sha256 matches the private commit record;
(iv) `parse_log` then `TopologyFold::replay` **from the reread bytes**.
Any failure returns `BarrierError` — so no `StablePrefix`, hence no CAS. Executed proofs:
the two-crash proof (a real child killed by abort after a complete-but-unsynced `merge_prepared`;
the child reports `synced <len>` then `cas` **in that order**, and `<len>` covers the
`merge_prepared` line; a real truncation then discards the unsynced `task_merged`; the log and the ref
still agree and the next resume appends `task_merged`) and
`barrier_sync_failure_before_cas_issues_no_cas_and_converges_after_loss` (an injected `SyncPrefix`
error: `cas_integration_entries == 0`, the ref unmoved, **nothing appended**, the durability ledger
empty for that log, and after the loss the candidate is still queued and integrates under sequence 0).

**One observation about (c), recorded because a later reviewer will hit it.** `BarrierHeld::from`
(`recover.rs:481`) is the **only** production call site of `StablePrefixBarrier::establish`, and it
passes `PrefixReread { first: m.clone(), second: m.clone() }`, `PrefixReplay { replayed: m }` and
`PrefixSync { synced_len: m.len }` — so all four of that validator's checks are vacuously true and the
call cannot fail. The barrier's substance is enforced upstream in `establish_stable_prefix` as set out
above, and the token's fields (`boundary`, `digest`) are what the census consumes, so **the guarantee
holds**; what does not hold is any claim that `StablePrefixBarrier::establish` is enforcing it at that
call site. Its four checks are exercised only by `src/runner/container/census/tests.rs` unit tests,
which is why a mutation of them would kill nothing else. Filed as an observation in §9, not as a
defect.

**What Q1 asks that G3 does not answer.** Coordinator-local holdings provably empty at process start;
