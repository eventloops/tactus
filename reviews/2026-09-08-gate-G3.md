### M4, the one survivor, is a redundancy and not a hole

The check M4 removes is **logically implied by two checks that both run before it** in the same
function, so no test can kill it:

1. `check_merge_prepared` opens by calling `MergePrepared::self_consistency()`, whose `Fast` arm
   refuses `FastProposesAnotherCommit` unless `proposed_sha == candidate_sha`.
2. It then calls `prepared_candidate(…, &prepared.candidate())`, which selects the recorded
   `PreparedCandidate` by `.filter(|prepared| prepared.candidate == *candidate)` — **full**
   `CandidateRef` equality, `commit_sha` included — and `MergePrepared::candidate()` builds that
   `CandidateRef` from `self.candidate_sha`. So reaching the third check at all requires
   `candidate_sha == candidate_record.candidate.commit_sha`.

(1) and (2) give `proposed_sha == candidate_record.candidate.commit_sha`, which is exactly what M4
deletes. The pair is *jointly* guarded — M6 shows that removing (1) alone is caught in 2 tests — so
the guarantee has a live witness; the third statement of it does not, and cannot. This is the
"redundant assertion defeats its own mutation" shape, not a coverage gap. **Not a finding.** It is
worth a one-line note in the source for the next reviewer, who will run the same mutation and reach
the same dead end.

## 5. Required artifacts #4 and #5 — replay-twice equality, and one linear commit per task

### #4 replay-twice equality

`Run::replay_twice_equal()` (`src/engine/topology/scaffold.rs:1287`) is not a self-oracle. It reads
the **on-disk** log (`durable_events()` = `std::fs::read(log.path())` then `TopologyFold::parse_log`),
replays it twice from `FrozenInputs`, asserts the two folds' `state()` equal, and then asserts the
**live incrementally-folded state equals the replay** — which is the load-bearing third assertion:
the live fold is built by `apply_delta` as events are appended, the replay by `TopologyFold::replay`,
and only agreement between two different code paths over the same bytes is evidence.

It is called at the end of every terminal shape in
`terminal_shape_coverage_table_drives_every_shape_and_each_converges_on_replay` (all 7 shapes),
at the end of the fast-path proof, and in the two-crash proof — where the replay-twice is over the
log that survived a **real** simulated power loss.

- `git rev-list --parents` gives **parents=1** for both new commits: the history is linear. No merge

- Sequence 0 is `Fast` and its `proposed` **is** `candidate_alpha` — the fast publication names the

`scaffold.rs`: `tasks: vec![task_of("alpha"), task_of("beta")]`), so the measured history is two
commits deep — one of each disposition, which is the interesting pair. The property measured is
per-`task_merged`, and the fold makes it inductive rather than a two-sample coincidence:
`check_transaction_start` refuses any sequence that is not `next_sequence` (`NonDenseSequence`), any
start while a transaction is open (`TransactionAlreadyOpen`), and any candidate that is not the
