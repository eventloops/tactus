### M4, the one survivor, is a redundancy and not a hole

The check M4 removes is **logically implied by two checks that both run before it** in the same
function, so no test can kill it:

1. `check_merge_prepared` opens by calling `MergePrepared::self_consistency()`, whose `Fast` arm
   refuses `FastProposesAnotherCommit` unless `proposed_sha == candidate_sha`.
2. It then calls `prepared_candidate(…, &prepared.candidate())`, which selects the recorded
   `PreparedCandidate` by `.filter(|prepared| prepared.candidate == *candidate)` — **full**
   `CandidateRef` equality, `commit_sha` included — and `MergePrepared::candidate()` builds that
   `CandidateRef` from `self.candidate_sha`. So reaching the third check at all requires
   `candidate_sha == candidate_record.candidate.commit_sha`.

(1) and (2) give `proposed_sha == candidate_record.candidate.commit_sha`, which is exactly what M4
deletes. The pair is *jointly* guarded — M6 shows that removing (1) alone is caught in 2 tests — so
the guarantee has a live witness; the third statement of it does not, and cannot. This is the
"redundant assertion defeats its own mutation" shape, not a coverage gap. **Not a finding.** It is
worth a one-line note in the source for the next reviewer, who will run the same mutation and reach
the same dead end.
